# Независимый ключ логов и secret-файлы

Перед включением этого изменения каждому Python-сервису нужен `LOG_PSEUDONYM_KEY` или `LOG_PSEUDONYM_KEY_FILE`. Без ключа процесс не запускается: fallback на `API_HASH` отсутствует. Генерация отдельного случайного ключа: `python -c "import secrets; print(secrets.token_hex(32))"`. Не используйте пример из CI; он публичный и предназначен только для тестов. Не передавайте реальные ключи в чат или GitHub.

Предпочтительный путь: оператор создаёт файл вне репозитория с ограниченным доступом, монтирует его read-only и задаёт `LOG_PSEUDONYM_KEY_FILE=/run/secrets/log_pseudonym_key`. Для `.env` допустимо значение из 64 hex-символов; `.env` должен быть недоступен посторонним. Ни `APP_SECRET_KEY`, ни Telegram credentials не подставляются автоматически. Код проверяет формат и запрещает очевидный односимвольный placeholder и точное повторение Telegram credentials; случайность нельзя доказать по формату, она обеспечивается генерацией.

Ротация: остановить workers, заменить файл атомарно, перезапустить сервисы, проверить readiness/outbox/pending jobs. Замена файла не перезагружает уже работающий процесс. Псевдонимы получателей в новых логах меняются, существующие логи не переписываются. Изменение ключа не меняет queue event IDs, privacy generation, подписки или Telegram recipient IDs. Независимые процессы с одним ключом и ID получают одинаковый псевдоним. Для плановой корреляции оператор заранее сохраняет границу времени ротации; обратное восстановление ID из псевдонима не предоставляется.

Secret loader поддерживает `BOT_TOKEN`, `API_HASH`, `DATABASE_URL`, `REDIS_URL`, `UKRAINEALARM_API_KEY`, `LOG_PSEUDONYM_KEY`, `PYROGRAM_SESSION_STRING`. При наличии `_FILE` файл имеет приоритет; пустой путь/файл, неверный UTF-8, специальный файл или превышение лимита останавливают запуск, env fallback не используется. Чтение ограничено 4097 байтами (16385 для Pyrogram session) из одного дескриптора: нельзя обойти лимит увеличением файла после проверки stat. На POSIX FIFO открывается nonblocking и отклоняется без ожидания writer. Символические ссылки на обычные файлы допускаются для projected secrets; безопасность каталога и ссылки обеспечивается правами хоста. Файлы устройств отклоняются после открытия; operator-controlled путь должен находиться в защищённом каталоге.

Pyrogram session из env/file теперь проходит общий Settings и одинаково маскируется вместе с log key, URL credentials и Bot API tokens в обоих sinks, включая exceptions. `repr(Settings)` скрывает поля секретов, обычный текст ValidationError не включает input. Это не запрещает явный `model_dump()`/`errors()` — их нельзя отправлять в лог, потому что структурированные данные могут содержать исходные значения. Session database на диске и сторонние библиотеки, которые напрямую печатают секреты, требуют отдельной проверки.

Проверки: `tests/test_secret_hardening.py` — отрицательные случаи, property test для 256-bit key, независимость от Telegram credential, ротация псевдонимов, конкурентное атомарное обновление файла, FIFO rejection на Linux, маскирование обоих sinks. Production-права файлов, vault, ротация на работающем окружении и отдельные роли Redis/PostgreSQL остаются UNTESTED/GAP. Этот пакет не включает развёртывание или передачу реальных секретов.
