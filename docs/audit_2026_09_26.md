## Подтверждённые дополнительные дефекты и исправления

1. **P1, семантика официального статуса**: `services/ukrainealarm.py:get_region_alerts` возвращал `[]` для JSON-объекта ошибки с HTTP 200. Poller записывал `0`. Исправлено: структура ответа и тип тревоги проверяются; неверный ответ вызывает ошибку и обычный путь failsafe, а не новый clear. Неверный status index вызывает полный запрос. Если Redis key исчез при неизменном index, состояние заново запрашивается. Redirect запрещён; тело HTTP ошибки не включается в exception.
2. **P1, владение адресной доставкой**: `worker/broadcaster.py:process_delivery_stream` резервировал сразу 20 задач, отправляя их последовательно. Срок idle рос и для ещё не начатых задач, поэтому второй воркер мог их забрать. Исправлено: count=1 в claim и read; ожидание rate slot ограничено 1–180 секунд; lease учитывает это ожидание, 120 секунд HTTP и 60 секунд запаса. Полная защита от длительного зависания процесса/Redis и неоднозначного Bot API ответа остаётся отдельной задачей.
3. **P2, незавершённые цепочки**: skipped stage не записывал терминальный результат, следующий этап ожидал sent и снова переносился в delayed queue. Исправлено: skipped записывается атомарно с ACK и распространяется вперёд. failed также передаётся следующему этапу через DLQ marker.
4. **P2, ядовитое время источника**: `core_shared/schemas.py` принимал naive/future timestamp. Исправлено: timezone обязателен, значение нормализуется в UTC, допустимый clock skew не более пяти минут; существующий invalid-payload путь завершает обработку. Проверено свойством Hypothesis для произвольных naive datetime.

## Проверки и пределы выводов

Локальный runtime: Windows, Python 3.12.14; production CI: Linux, Python 3.11. Для локальных unit tests tgCrypto не установлен: wheel для этого runtime отсутствует, сборка требует MSVC. Production requirements и lock не изменены. Полный Linux CI должен проверить реальные Redis/PostgreSQL, контейнер и supply chain. Рабочий Telegram, реальный API ключ, production БД и backup в этой сессии не использовались.

После последовательного review и включения A–D обоснована более высокая оценка качества кода; общий 9/10 не подтверждается до прохождения G–H. Оценку main выше нельзя автоматически переносить на сервер: версия развёрнутого приложения неизвестна.
