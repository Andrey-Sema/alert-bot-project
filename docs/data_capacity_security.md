# Дані, ємність і секрети

## Фактична аудиторія та пропускна здатність

Після застосування Alembic-міграцій бот записує один рядок на користувача за UTC-добу. `interacted` означає `/start`, зміну налаштувань або ACK; `delivered` означає успішну відповідь Bot API. Команда `python -m alert_bot_project.scripts.mau_report` виводить лише дві агреговані величини за останні 30 календарних діб. До першого повного 30-денного вікна це неповний MAU. Відсутність доступу до робочої БД означає, що фактична поточна цифра невідома.

Максимальна безпечна аудиторія окрема від MAU. Її потрібно вимірювати на ізольованому стенді з профілями 1, 5 і 20 постів на хвилину, часткою підписників 10/50/100%, однією і трьома стадіями доставки, а також 10-хвилинними збоями Redis, PostgreSQL і Bot API. Зберігати p50/p95/p99 часу від отримання поста до успіху Bot API, 429, retry, DLQ, CPU, RAM і кількість DB-з'єднань. Максимальне N — остання пройдена ступінь із погодженим SLO та нульовими втратами. Локальний Redis-стрес-тест не замінює цей вимір.

## Видалення і строки зберігання

`/delete_me` у приватному чаті вимагає підтвердження. Операція видаляє профіль, тригери та денну активність каскадом у PostgreSQL, прибирає поточні завдання зі списку затримок і delivery stream та ставить покоління одержувача в Redis. Старі завдання не доставляються навіть після нового `/start`. Завдання старше семи днів за часом отримання джерела відкидається. Маркер видалення зберігається в Redis вісім днів. Щоденний процес видаляє рядки активності старше 30 днів.

Резервні копії PostgreSQL, Redis AOF і журнали керуються інфраструктурою. Оператор має встановити і задокументувати строк їх зберігання та процедуру видалення відповідно до своєї політики; видалення з активної БД не стирає вже створені копії. Відмова Redis або БД під час видалення повертає помилку, тому запит треба повторити. Для експорту профілю оператор може зробити автентифікований SQL-запит до `user_settings` і `user_triggers`; публічний endpoint експорту не надається.

## Секрети і мережа

Для `BOT_TOKEN`, `API_HASH`, `DATABASE_URL`, `REDIS_URL`, `UKRAINEALARM_API_KEY`, `LOG_PSEUDONYM_KEY` можна задати однойменну змінну з суфіксом `_FILE`; файл читається під час старту й має перевагу над env-значенням. Pyrogram також підтримує `PYROGRAM_SESSION_STRING_FILE`. Монтуйте такі файли лише потрібним контейнерам, лише для читання, з правами власника `0400`; не включайте їх до образу чи резервних копій коду. На ротації перезапускайте відповідні сервіси, перевіряйте outbox і pending stream, потім відкликайте старі токени. Зовнішній Redis URL має використовувати `rediss://`; локальний контейнерний Redis ізольований bridge-мережею. PostgreSQL перевіряє сертифікат і ім'я сервера за системним CA.

## Відтворювана збірка

`requirements.lock` містить зафіксовані транзитивні версії та SHA256. Оновлюйте його командою `uv pip compile --python-version 3.11 --generate-hashes --output-file requirements.lock requirements.txt` в окремому PR. CI інсталює залежності з `--require-hashes`, запускає pip-audit, створює CycloneDX SBOM і збирає Docker-образ. GitHub Actions та базові/інфраструктурні образи закріплені SHA/digest. Новий digest перевіряйте разом із журналом релізу, тестами і SBOM.

Незалежний ключ псевдонімів обов’язковий; немає fallback на API_HASH. Див. [secret_hardening.md](secret_hardening.md).
