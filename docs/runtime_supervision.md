# Контроль критических фоновых задач

Worker контролирует source consume (включая начальный drain), каждый delivery
consumer, delayed delivery, pending recovery, queue metrics, trigger
reconciliation и activity retention. Poller официального API контролируется,
если API настроен; его нормальный выход при отключённом API не является сбоем.
Scraper контролирует outbox replay и source catch-up. Миграция старых source
маркеров — разовая задача, которой разрешён нормальный выход.

`core_shared/supervision.py` владеет задачами и ждёт первое завершение либо
сигнал остановки. Исключение, отмена или нормальный выход критической задачи
до shutdown приводят к ошибке сервиса. Исходное исключение сохраняется как
cause и записывается существующим журналом с редактированием секретов.
Одновременный shutdown не скрывает уже завершившуюся задачу с исключением.
Остальные задачи отменяются и ожидаются до закрытия Redis/Telegram ресурсов.
Ошибки инициализации worker также закрывают эти соединения.

После SIGINT/SIGTERM завершается supervisor, затем закрываются providers.
Worker не удаляет consumer с pending jobs: существующий XAUTOCLAIM должен
перехватить их после восстановления. Scraper сохраняет SQLite outbox.
Compose `restart: unless-stopped` отвечает за перезапуск после аварийного выхода;
сам supervisor не запускает второй экземпляр обработчика.

Тесты `tests/test_supervision.py` выполняют настоящий asyncio scheduling:
ошибки, неожиданный return, независимая отмена, отмена родителя, ошибка factory,
shutdown/failure race с Hypothesis и entrypoints worker/scraper с провайдерами
test doubles. Они проверяют завершение соседних задач и закрытие ресурсов.
Это дополняет частичное доказательство ASVS V16.5.3. Оно не подтверждает
требование V16.5.4 о сохранении доступности всего процесса при каждой ошибке.

## Оставшиеся границы

Healthcheck пока проверяет зависимости, а не прогресс отдельных циклов.
Supervisor обнаруживает завершение задачи, но не зависание, подавленное
исключение или бесконечный retry. Heartbeat/progress watchdog, верхняя граница
cleanup для задач, подавляющих CancelledError, фактическое время перезапуска,
доставку после рестарта и alarm routing нужно проверить отдельно. Runtime
проверки на реальных providers и production recovery не выполнялись.
